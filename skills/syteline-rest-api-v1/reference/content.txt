Chapter 3: Using the REST API

You can use the REST API to access IDOs from a client-side web project, a mobile app, or an Internet of Things
(IoT) device to perform IDO-related operations, such as loading or updating collections, or running methods.
REST API is another layer on top of the IDO request interface that uses the IDO request XML schema.

Integration with ION API
The REST APIs are shown to customers through Infor ION API, so the customers can have one common
authentication mechanism and a consolidated view, and can consume the APIs from many Infor applications.
The REST APIs are developed so the ION API can consume them using the OAuth 1.0a zero-legged authentication
mechanism.
To know how to use Infor ION API and how to interact with the swagger documentation for the API methods,
see the Infor ION API Administration Guide.

Authentication
The REST API offers security by requiring that either a security token or a valid OAuth 2.0 bearer token to be
passed in the Authorization header of the API requests.
The REST API currently supports these authentication schemes:
•
•

Mongoose security token
OAuth 1.0a zero-legged authentication

Mongoose security token
A security token can be acquired by using the GetSecurityToken API. This API is used to authenticate requests
when the REST API is being called directly.

Infor Mongoose IDO Integration with External Applications Guide | 35

Using the REST API
security tokens are unique for each user and should be stored securely. These tokens only expire when the
user or configuration becomes non-existent, or when the user changes the password.

OAuth 1.0a zero-legged authentication
OAuth 1.0a authentication is a signature that is computed using a consumer key and a matching consumer
secret, along with the details of the request.
For the REST API, the OAuth 1.0 with HMAC-SHA1 algorithm is used when the REST API is being called through
the ION API.
